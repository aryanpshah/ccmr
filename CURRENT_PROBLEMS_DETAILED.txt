2. 🔴 PRIMARY PROBLEM: OVERFITTING vs GENERALIZATION GAP
================================================================================

CLIENT SYMPTOM: "Overfit tests work well BUT normal testing produces low values"

ROOT CAUSE ANALYSIS:

┌────────────────────────────────────────────────────────────────────────────┐
│                     OVERFITTING ISSUE BREAKDOWN                            │
├────────────────────────────────────────────────────────────────────────────┤
│                                                                            │
│  Overfit Test (Good Performance):                                         │
│  ├─ Model sees SAME 1-2 samples repeatedly                                │
│  ├─ Learns specific features of those exact volumes                       │
│  ├─ Achieves high Dice (>0.9) through memorization                        │
│  └─ ✅ This proves the MODEL CAPACITY is sufficient                       │
│                                                                            │
│  Normal Test (Poor Performance):                                          │
│  ├─ Model sees DIFFERENT samples from test set                            │
│  ├─ Hasn't learned GENERALIZABLE features                                 │
│  ├─ Gets low Dice (<0.7 for L5, <0.85 for L10)                            │
│  └─ ❌ This proves REGULARIZATION is insufficient                         │
│                                                                            │
│  THE GAP = UNDERFITTING ON THE DISTRIBUTION                               │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

CONCRETE EVIDENCE:
→ L5 achieves 0.667 Dice (poor)
→ L10 achieves 0.823 Dice (marginal)  
→ L20 achieves 0.892 Dice (good)
→ With only 5-10 training samples, model CANNOT generalize

WHAT THIS MEANS:
✓ Model architecture is FINE (proven by overfit success)
✓ Loss function WORKS (proven by training loss decreasing)
✗ Model is MEMORIZING not LEARNING features
✗ Need MORE regularization (augmentation, weights, etc.)

3. 🔴 HIGH PRIORITY FIXES (Must Address)
================================================================================

FIX #1: INCREASE DATA AUGMENTATION (Critical for L5/L10)
────────────────────────────────────────────────────────
Current (Too Conservative):
  RandScaleIntensityd(factors=0.05, prob=0.5)
  RandShiftIntensityd(offsets=0.05, prob=0.5)

Recommended:
  RandScaleIntensityd(factors=0.15, prob=0.8)  ← 3x stronger, more frequent
  RandShiftIntensityd(offsets=0.15, prob=0.8)  ← 3x stronger, more frequent
  
  # Add these:
  RandAffined(
      prob=0.7,
      rotate_range=(-0.2, 0.2),  # ±11 degrees
      scale_range=(-0.15, 0.15), # ±15% scaling
      mode=("bilinear", "nearest")
  )

WHY: With only 5-10 training samples, MUST artificially expand the dataset


FIX #2: IMPROVE CLASS IMBALANCE HANDLING
─────────────────────────────────────────
Current Class Weights:
  [0.05, 1.0, 1.0, 1.5, 2.0, 2.5, 3.0, 3.0, 3.0]

Problem: Class 1 (smallest structure) still gets Dice=0.484 with L5

Solution A - More Aggressive Weights:
  [0.01, 5.0, 2.0, 3.0, 3.5, 4.0, 4.5, 5.0, 5.0]
  #    ^^^^ Emphasize small structures 5x more

Solution B - Focal Loss (RECOMMENDED):
  from monai.losses import DiceFocalLoss
  
  loss_function = DiceFocalLoss(
      include_background=True,
      to_onehot_y=True,
      softmax=True,
      gamma=2.0,          # Focus on hard examples
      lambda_dice=0.7,    # 70% Dice
      lambda_focal=0.3,   # 30% Focal CE
      weight=class_weights
  )

WHY: Standard Dice loss doesn't penalize small structure errors enough


FIX #3: REDUCE LEARNING RATE + ADD WARMUP
──────────────────────────────────────────
Current:
  lr_max = 2e-4  (scratch)
  lr_max = 6e-5  (finetune)

Recommended:
  # Scratch
  lr_max = 1e-4
  lr_min = 1e-5
  warmup_epochs = 20
  
  # Fine-tune  
  lr_max = 3e-5
  lr_min = 3e-6
  warmup_epochs = 10

Implementation:
  from torch.optim.lr_scheduler import LinearLR, SequentialLR
  
  warmup = LinearLR(
      optimizer, 
      start_factor=0.1, 
      total_iters=warmup_epochs
  )
  cosine = CosineAnnealingLR(
      optimizer,
      T_max=max_epochs - warmup_epochs,
      eta_min=lr_min
  )
  scheduler = SequentialLR(
      optimizer,
      schedulers=[warmup, cosine],
      milestones=[warmup_epochs]
  )

WHY: High LR causes unstable training with batch_size=1


FIX #4: INCREASE PATCH SIZE (If GPU Allows)
────────────────────────────────────────────
Current:
  roi_size = (128, 128, 128)

Recommended:
  roi_size = (160, 160, 160)  # or (192, 192, 192)

GPU Memory Requirements:
  128³ ≈ 2.1M voxels → ~4-6 GB
  160³ ≈ 4.1M voxels → ~8-10 GB
  192³ ≈ 7.1M voxels → ~14-18 GB

WHY: Whole-heart segmentation needs larger context to see full structures
